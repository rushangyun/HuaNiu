# app/core — 契约层与全局装配

整个后端**唯一"谁都能依赖、但自己不依赖任何人"**的一层。

| 文件 | 干什么 | 为什么不这么干不行 |
|---|---|---|
| `events.py` | 定义前后端之间**所有**事件（TOKEN / TOOL_START / TOOL_END / ROUND / DONE / ERROR / VISION_* / AUDIOBOOK_*） | 事件是**唯一的跨端契约**。没有它，前端就得猜后端返回什么，两边必然各写各的然后漂移 |
| `config.py` | 所有可配项集中一处（模型地址、端口、视觉阈值、TTS、存储路径） | "换台机器要改的东西"散落在业务代码里就一定会漏改，而且报错看不出根因 |
| `container.py` | 依赖容器，**只放字段、不放构造逻辑** | 构造（组装）是 `main.py` 组合根的职责。容器里写构造逻辑，单测时就换不掉零件 |
| `errors.py` | 统一错误类型 | 各层自定义异常，API 层就得写一堆 if-else 翻译，错误语义会漂移 |

## 关于事件契约

前后端解耦的关键就在这里：**后端只管按契约发事件，前端只认契约类型**。
所以换模型、换后端框架、把 React 换成 Vue，只要契约不变，两边各自独立替换。

`web/src/types/events.ts` 由 `scripts/gen_event_types.py` **用 AST 解析本文件自动生成**，
不手抄 —— 手抄类型是解耦架构最常见的翻车方式：两边都觉得自己没错，运行时才发现对不上。
