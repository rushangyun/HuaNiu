# app/agent — 手写 Agent 运行时（不用框架）

| 文件 | 干什么 | 为什么不这么干不行 |
|---|---|---|
| `runtime.py` | tool-calling **主循环**：模型输出 tool_call → 执行工具 → 结果喂回模型 → 再问，直到不再调工具或达到 `max_tool_rounds` | 这就是 Agent 的全部本质，本身只有几十行。套 LangChain 等于给自己加一层黑盒，出问题还得去猜框架内部在干什么 |
| `prompts.py` | 上下文装配（系统提示 + 历史 + 工具结果） | 拼上下文散在主循环里就改不动；而且本地 7B 模型上下文有限，必须**主动裁剪**（`max_history_turns=12`），塞满了会"失忆"/退化 |
| `tools/` | 工具实现，见 [`tools/README.md`](tools/README.md) | — |

## 两条关键防护

- **`max_tool_rounds=6`** —— 小模型会陷入"反复调同一个工具"的死循环，
  没有轮数上限会把显存和时间烧光。
- **上下文预算** —— 本地模型上下文一超就退化，必须主动裁剪历史，不能全塞。

## 为什么不用框架

不是不想用，是**这台机器用不起**（内存 16GB，实测空闲仅 6.5GB），
而且主循环本身几十行，套框架带来的黑盒成本大于收益 —— 每一行都能讲清为什么，才是目的。
