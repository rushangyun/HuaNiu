# app/audiobook — 有声书子系统（解析 → 合成 → 导出）

| 文件 | 干什么 | 为什么不这么干不行 |
|---|---|---|
| `chunking.py` | 切分：章 → 句 → **按引号切成旁白片/对白片** → 分批 | 顺序必须是「**先按引号切、再在非引号区按句切**」。反过来会把跨句引号（？ 落在引号内）劈成两半，后半段带悬空引号被判成对白 → **旁白被角色声线朗读** |
| `parser.py` | 调本地 LLM 逐片段标注（角色/情绪/语速/停顿），失败重试 3 次再降规则兜底 | 不让模型算字符偏移（7B 会把偏移算飞、输出越界被 `max_tokens` 截断成坏 JSON）；**对白必须带引号**，否则强制判为旁白 |
| `pipeline.py` | 编排：分批 → 标注 → 性别判定 → 建角色名册 → 落库 | 性别**不能按出现顺序猜**：用「LLM 上下文提示 + 代词归因（他/她 → 前方最近角色名）」，冲突时代词优先 |
| `repo.py` | 所有 SQLAlchemy 读写 | 换数据库只改这一个文件；SQLite 用 StaticPool + busy_timeout，多线程不锁死 |
| `worker.py` | 合成队列：单段一个 job、失败指数退避重试、md5 缓存、断点续跑、ffmpeg 合并 | TTS 是外部依赖，必须能重试和续跑，否则整本跑到一半失败就全废 |
| `bus.py` | 进度事件总线（SSE 推解析/合成进度） | 前端靠它显示进度条，不用轮询 |
| `media.py` | ffmpeg 合并章节 / 全书 | 合并失败不能连累已生成的段落音频（它们在 `seg/` 里还在） |
| `normalize.py` | 文本归一化（数字/符号转读法） | TTS 直接读"100元"会读错，要先转成"一百元" |
| `models.py` | 数据表定义 | — |

## 两条铁律

1. **只标注，不改写** —— 文本一律由程序按原文切片回填，绝不采用模型返回的"改写体"。
2. **旁白与对白绝不合并成一段** —— 否则旁白会被角色声线朗读。

## 修复记录（真实踩坑）

- 曾出现「解析成功但角色是句子碎片、正文切成 60 个碎片段」：
  根因是让 7B 模型自己算字符偏移并切分，偏移算飞、输出越界被截断 → JSON 坏掉 → 静默降级规则兜底。
  改为「程序切分 + 模型只标注」后解决。
- 曾出现「段落重复」：分块留 100 字重叠，重叠段被解析两次落库两次。改为按片段边界分批（无重叠）后解决。
